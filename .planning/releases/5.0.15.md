# Release 5.0.15

- Date: 2026-11-09 (Asia/Shanghai).
- Status: published and verified complete. Latest shipped npm: 5.0.15.
- Candidate scope: Phase 85 force-update authorization only. The release carries
  the authorization paths for the force-update pass (declared ownership with
  marker proof, qualified marketplace registration, git-origin proof for clones,
  the official npm upgrade path for global CLI tools), the ownership receipt fix
  on the refresh path, the `agents-skills` ownership root, the GSD declaration
  marker correction and the honest kept-existing summary. No runtime mode,

- The user explicitly authorized the publication ("顺便发一下新版本").

## Released Changes

- `harnessed setup` can now update the components it installed. The force-update
  pass refused every component since v5.0.0 because nothing could prove
  ownership, and its summary told the user to re-run setup - advice that could
  never work. Ownership is now provable per install channel: a declared
  skill-pack footprint whose every existing entry passes the manifest's own
  marker check, a marketplace plugin registered under the exact qualified
  identity the install command installs, a checkout whose git origin is the URL
  the manifest clones from, and a global npm package (scoped per package name).
  Everything that does not prove out is still refused.
- A force update no longer fails on the ownership receipt it writes itself: an
  authorized refresh records the footprint it proved instead of an empty "new
  paths only" set.
- The manifest ownership contract gained the `agents-skills` root - the real
  location of a skill the `skills` CLI installs without `--global`.
- The GSD pack's ownership marker now matches what the pack actually ships, so
  its declaration proves something.
- Global npm tools (`ctx7`, `playwright-cli`) take part in the force-update
  pass through the official `npm install -g` command, with the consent prompt
  naming the system-scope upgrade.
- The update summary no longer promises a retry that cannot succeed.
