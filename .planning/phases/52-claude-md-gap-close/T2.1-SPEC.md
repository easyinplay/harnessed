# T2.1 — gate facts 生产链

## 问题(审计 S2)

判据写得完整,运行时无辨别力,三个原因叠加:

1. `buildDefaultGateContext` 把判据值全设成「会 fire」的一侧(`open_decisions:2` / `approaches:2` / `core_algorithm:true` / `error_cost:'high'` / `is_critical_module:true` / `is_complex_architecture:true`),而 `workflows/` 下**零处**传 `--context` → 等价「永远 fire」。
2. `skips_when` 是死配置:resolver 支持 `.skips`(`judgmentResolver.ts:92-96`),但所有 `delegates_to[].gate` 一律引 `.fires`,❌ 跳过条件从不求值。
3. 最硬的 🔒 反而默认关:`phase.type` 默认 `'general'`,不在 `strategic-gate` 的 `['new_project','new_milestone','new_feature']` 里,且 `'general'` 不在 `PhaseType` 枚举内(out-of-schema)。

## 裁决(D2:混合来源)

能确定性推导的由 harnessed 推;判断题由模型在 SKILL step 1 填。

## 设计

### D-1 `harnessed facts <master>` 子命令(NEW)

一条命令解决「需要哪些 fact / 哪些能自动填 / 剩下的留给模型」:

- **枚举需求**:解析该 master 的 `delegates_to[].gate`(与 NEW 的 `skip_gate`)引到的 judgment trigger,取其 `fires_when` / `skips_when` 里出现的 fact 名。**只要求真正 gate 了东西的 fact**,不是 40 个 fact 全填。
- **自动填**:确定性可推的直接给值(见 D-2)。
- **留空**:判断题输出 `null` + 一行英文说明该 fact 判什么,供模型填。
- 输出 JSON 到 stdout,`--out <path>` 可落盘。

SKILL step 1 的 locked spec 环节把这份 JSON 填完 → step 2 用 `--context-file` 传。

### D-2 确定性推导集(harnessed 侧)

| fact | 来源 | 备注 |
|---|---|---|
| `subtask.lines` | `git diff --numstat`(+ `--cached`)总行数 | 无 git / 空 diff → 留 null 交模型,**不要**填 0(0 会让 `lines < 20` 的 main-session-fallback 误 fire) |
| `files_touched`(NEW fact) | `git diff --name-only` 计数 | 补进 `PhaseShape`(`additionalProperties:false` 必须同步 schema);兑现 phase-gate 缺的「scope > 5 文件」判据 |
| `phase.stage` | 现有 ledger / `current-workflow.json` | checkpoint 已知,不必问模型 |

其余一律留 null 交模型。**不推 `open_decisions` / `error_cost` / `approaches` 这类** —— 从代码推是造假信号,比默认全开更危险。

### D-3 `--context-file <path>`(NEW,与 `--context` 并存)

`--context` 保留兼容。新增 `--context-file` 避 Windows 引号坑(项目历史:嵌套 JSON 在 PowerShell/Git Bash 双层转义反复出错)。两者同时给 → `--context-file` 先合并、`--context` 后合并(命令行显式覆盖文件),冲突行为写进 help 文本 + 单测。

### D-4 fact 缺失语义(接 ADR-0038)

- `--context-file` 里 fact 为 `null` → **视为未提供**,回退 `buildDefaultGateContext` 的默认值(不是塞 null 进 context,否则 `null == 'high'` 求值出意外假)。
- 模型没填完 → 行为等于今天(默认值),不退化。
- **默认值本身要改**:把「安全网偏向开火」的默认从判据值上撤下来是本 slice 的核心,但**改哪些、改成什么**是 OQ2。

### D-5 `.skips` 接线(NEW `skip_gate` 字段)

`delegates_to[]` 新增可选 `skip_gate: judgments.<file>.<trigger>.skips`。语义:

- `gate` fire 且 `skip_gate` 未给 → 跑(今天行为)
- `gate` fire 且 `skip_gate` 求值 true → **veto,跳过**(记 ledger reason)
- `gate` 未 fire → 不跑(与 `skip_gate` 无关)
- `skip_gate` 撞 undefined variable → **不 veto**(保守方向:保留 gate 的决定;与 ADR-0038 的 fail-closed 方向相反是有意的 —— 那里 fail-closed 是「不确定就不跑」,这里 veto 的 fail-closed 等价「不确定就跑」,两者都是「不确定时不做更多事」。此不变式写进 ADR + 单测)

`skips_when` 已有的三个 judgment(`phase-gate` / `subtask-gate` / `tdd-gate`)首批接线。

### D-6 `phase.type` 默认值修正

`'general'` 出 schema。改成 `PhaseShape.type` 枚举内的值,且**不能**让 `strategic-gate` 默认 fire(方法论自己写了 bug 修复 / 技术债要跳过 office-hours)。候选:枚举里加 `'general'` 使其合法,或默认取枚举内某个不触发战略门的值。实施时二选一并在 ADR 说明。

## 验收

- `harnessed facts task` 输出的 fact 集 = `task` 的 gate/skip_gate 实际引用的 fact 集(用测试对账,不是硬编码列表)
- 推导集三项各有单测(含无 git / 空 diff → null 而非 0)
- `--context-file` 与 `--context` 合并顺序有单测;非法 JSON 报错文案与 `--context` 一致
- `skip_gate` 四种组合态各一测,含 undefined-variable 不 veto
- 全量 gate 脚本绿 + `PhaseShape` 加 `files_touched` 后 `pnpm build && pnpm build:schema` 并提交 `schemas/`(typebox 铁律)
- en-default byte-identical;i18n parity ×3

## Open Questions(需用户裁决,阻塞 ready-to-execute)

- **OQ1 `harnessed facts` 这个新 CLI 面可接受吗?** 替代方案是不加子命令、由 SKILL 文本直接写死要填的 JSON 模板(零新 CLI,但模板与 judgments 会漂移,且无法自动填推导集)。我推荐加子命令 —— 它把「需要哪些 fact」从 SKILL 文本里的静态副本变成从 yaml 派生,消除漂移。
- **OQ2 默认值撤到什么程度?** 三档:(a) 判据 fact 全部改成「不 fire」的一侧,没填就啥都不跑 —— 最干净但激进,漏填即静默不跑治理关卡;(b) 判据 fact 留空(`undefined`),靠 ADR-0038 fail-closed 决定 —— 语义最一致,但 fail-closed 当前是「不跑」,后果同 (a);(c) 只撤明显过度的几个(`is_critical_module` / `is_complex_architecture` / `core_algorithm` / `error_cost`),其余保留安全网 —— 最保守,但「判据有辨别力」只做了一半。我倾向 (c) 起步 + 用 `harnessed facts` 的覆盖率数据(哪些 fact 模型真的会填)在下一轮决定是否推进到 (a)。
